## 2026-09-18 — Kafka live end-to-end through CI/CD; four root-cause faults fixed

- **Kafka is running.** Strimzi 1.2.0 / Kafka 4.3.1, KRaft, one broker on the
  `stream` node, topic `market.trades` (6 partitions, 7-day retention).
  Verified with a real produce/consume round trip from a laptop.
  Bootstrap: `tsp-kafka-bootstrap.kafka.svc:9092` internal, `:30092` external.
- **Four faults, each hiding the next** — full account in `K8S_MIGRATION.md`:
  1. `--advertise-address` defaulted to the public IP → no pod could reach the
     API server. 2. Flannel tunnelled VXLAN over public IPs → no cross-node pod
     traffic. Both from `--node-external-ip`, both live since Sep 9, invisible
     because every kube-system pod runs on the control plane. 3. Strimzi 0.45
     can't parse k8s 1.36's `/version` (fabric8 `emulationMajor`). 4. Strimzi 1.x
     serves only `v1` CRDs, and Helm never upgrades a chart's `crds/`.
- **Third Terraform stack: `tailscale/`** — owns the tailnet ACL, adopted
  verbatim from the live policy and imported so the first plan was a no-op.
  Separate because it decides whether CI can reach the cluster.
- **CI now applies all three stacks.** The `terraform-apply` guard that refused
  SSH-requiring plans was stale since CI joined the tailnet; relaxed to a
  warning. CRD upgrades, `setup-terraform` retry, and atomic Helm added.
- **Kafka console** (Redpanda Console, Go, 128Mi) on the observability node,
  published to the tailnet by the Tailscale k8s operator — no public exposure,
  Tailscale identity is the auth. Ingress for HTTPS pending approval.
- **Known-open:** broker is `Burstable` not `Guaranteed` (CPU request ≠ limit);
  replication factor 1; `terraform_data.tailscale_router` still can't be applied
  from CI (public SSH path by design).
- **Next:** Phase 3 — Redis and the backends as Deployments.
